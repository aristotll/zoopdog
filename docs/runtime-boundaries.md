# Runtime boundaries

The website, the two standalone userscripts and the local inspection CLI share dictionary data;
`zd-extension/` is the historical name of the shared source directory. Build and publication
commands are in [build.md](build.md), and the cross-repository reader contract is in
[local-mode.md](local-mode.md).

| Boundary | Input and output | Owner |
| --- | --- | --- |
| Dictionary identity | Source rows `{vn, en: [{def, pos}]}` become ordered grouped entries `{key, headwords, en}`; an optional sense `headword` associates a sense with a non-primary spelling. | `scripts/lib/dictionary-identity.js` |
| Popup dictionary | Each key maps to `[[headwords, senses]]`; each sense is `[def, pos]` or `[def, pos, headword]`. | `scripts/build-popupdict-userscript.js` |
| Rendering preference | Ordered rows contain `vi`, `nom[]`, and optional `caseSensitive`; exact-case rows and casefolded rows are distinct. | `scripts/user-nom-order.js` and reader `nom_order.py` |
| Browser dictionary | Metadata `{schemaVersion, revision, entryCount, payload?}` identifies grouped JSON. The coordinator returns `ready-current`, `ready-refreshed`, `ready-stale`, or `unavailable`, with an error and remedy for failures. | `zd-extension/js/zd-dictionary-runtime.js` |
| Popup frame | A sandboxed frame receives bounded, versioned messages over a MessageChannel; the page owns geometry and pin storage. | `zd-extension/js/zd-popup-protocol.js`, `showframe.js`, `frame.js` |
| Local HTTP | The manager adapter sends a method, path, query, optional JSON body and timeout; success resolves parsed JSON and errors retain status and payload. | `scripts/userscript/local-transport.js` |
| Local selection and modal geometry | Selection extraction and drag-range handling take a document and caret/selection adapters; modal geometry takes storage, domain and viewport callbacks. The runtime owns event wiring and modal state. | `scripts/userscript/local-selection.js`, `local-modal-geometry.js`, `local-modal.js`, `local-selection-bar.js` |
| Explored-link tools | Inline buttons after each Google result title (`decorate`) and a hover pill for an uncoloured link take an injected document and `eligible`/`refresh`/`blacklist` callbacks; they only draw and route clicks. The runtime owns the keys, the server calls and the blacklist modal. | `scripts/userscript/local-explored-tools.js`, `local-explored-highlight.js`, `local-modal-build.js` |
| Local entry preview and modal guard | A renderer takes an injected document and renders server diff rows with text nodes; a guard prevents duplicate submissions while preserving pre-existing button state. Modal event handlers own preview and confirmation. | `scripts/userscript/local-entry-diff.js`, `local-modal-guard.js`, `local-nom-form.js`, `local-nom-order-form.js` |
| Offline Nôm review | `read`, `write`, `has` and `add` operate on a supplied string store; entries are `{vi, context, ts}`. | `scripts/userscript/nom-review-store.js` |
| Popup runtime fragments | `popupdict.runtime.js` keeps the userscript header, the dictionary accessor, settings, lookup and the `main`/`startPopup` event wiring. Four fragments were moved out of it verbatim, with no renaming: the offline Nôm review queue, export panel and selection bar; the `Highlighter`; `ResultPopup` with pin storage, viewport helpers and placement; and definition rendering with `escapeHtml` and the Trusted Types `zooSetHTML`. They are plain top-level declarations that share the IIFE's scope, and each file's header comment names the globals it relies on. | `scripts/userscript/popup-nom-review.js`, `popup-highlighter.js`, `popup-result.js`, `popup-render.js`, `popupdict.runtime.js` |
| Ruby userscript helpers | `zdCreateBackoffPoll({intervalMs, maxMs, run, setTimeout, clearTimeout, isActive?})` is the adaptive safety-net timer both ruby runtimes use: it starts at `intervalMs`, doubles to `maxMs` while `run()` reports no work, snaps back when it does, `wake()` restarts only a backed-off timer, and `stop()` cancels it. Timer functions are injected. The scan loops, queues and observers of the two runtimes are deliberately not shared (nom-ruby is synchronous, time-sliced and tracks ownership; cjk-ruby is asynchronous around requests and a cache); neither are `addStyle`, `chooseMode` or `EXCLUDED_TAGS`, which differ in behaviour. | `scripts/userscript/zd-userscript-common.js`, `nom-ruby.runtime.js`, `cjk-ruby.runtime.js` |
| Local runtime fragments | `popupdict-local.runtime.js` was split verbatim (no renames, no body changes) into ten fragments, concatenated in this order after the pure `local-*.js` helpers and ahead of the seam: `local-server.js` (reader-server settings, transport instance, probe), `local-explored-engines.js` (`ZOO_SEARCH_ENGINES`, `ZOO_ENGINE`), `local-explored-highlight.js` (link keys, painting, `zooStartExploredHighlight`), `local-requests.js` (debounce, race guard, fetchers, notes-all streaming), `local-form-helpers.js` (clipboard, "Refresh all" wiring, datalists), `local-modal.js` (toast and modal mechanics, `ZOO_MODAL_IDS`, form states), `local-selection-bar.js`, `local-nom-form.js`, `local-nom-order-form.js`, `local-modal-build.js` (blacklist modal, `zooBuildModals`). `popupdict-local.runtime.js` keeps only the header and the `zooLocal = {...}` seam, last. A top-level `var x = expr;` reads another fragment's `var` here (`ZOO_LOCAL_BASE` feeds `zooHttpRequest`, `ZOO_SEARCH_ENGINES` feeds `ZOO_ENGINE`, the `createZoo*` factories feed the instances in `local-modal.js`), so the order in `LOCAL_RUNTIME_SOURCES` is load-bearing. | `scripts/userscript/local-server.js`, `local-explored-engines.js`, `local-explored-highlight.js`, `local-requests.js`, `local-form-helpers.js`, `local-modal.js`, `local-selection-bar.js`, `local-nom-form.js`, `local-nom-order-form.js`, `local-modal-build.js`, `popupdict-local.runtime.js` |
| nom-ruby runtime fragments | Three groups of `nom-ruby.runtime.js` were moved out verbatim (no renames, no body changes) and are inlined by `build-nom-userscript.js` at placeholders left in their original positions, so the built script has the same declarations in the same order: `nom-ruby-scan.js` (mutation handling, time-sliced scan job, safety-net poll), `nom-ruby-annotate.js` (`annotateTextNode`, `createRuby`, `wrapMatches`, `wrapPiece`, `wordSpans`, `annotateAcrossNodes`, overlay recording) and `nom-ruby-lifecycle.js` (remove/hide/show/disable/render and the toggle button). Left in `nom-ruby.runtime.js`: the userscript header, the inlined shared sources, the embedded maps, settings and state, the per-site fixes, mode choice and CSS (they carry the `__ZOOPDOG_LOCAL_SITE_RULES__` and `__ZOOPDOG_NOM_FONT_SRC__` placeholders, and a structure test asserts the former stays in the runtime), shadow-root watching, `addStyle`, `main`. `test/nom-ruby-runtime.test.js` builds its own placeholder map and lists the three fragments. | `scripts/userscript/nom-ruby.runtime.js`, `nom-ruby-scan.js`, `nom-ruby-annotate.js`, `nom-ruby-lifecycle.js` |
| Annotation ownership | A cross-node match tracks its source segments and inserted nodes; changed or removed sources retire the affected match before rescanning. | `scripts/userscript/nom-ruby-annotate.js`, `nom-ruby-scan.js` |

The userscript builders inline the shared browser sources in declaration order into their existing
IIFEs. The popup builder keeps two ordered lists, `PUBLIC_RUNTIME_SOURCES` and `LOCAL_RUNTIME_SOURCES`
(the latter only for the `-local` build), and renders both with one loop; the whole list is placed
where `__ZOOPDOG_RUNTIME_SOURCES__` sits, ahead of `popupdict.runtime.js`'s own body. Function
declarations hoist across fragments, but a top-level `var x = expr;` does not, so a fragment may not
read another fragment's `var` while it is being concatenated; keep such initialisers independent of
each other (the moved popup fragments only read them from inside functions that run later, from `main()`; the local fragments are the exception noted in the table above).

Local-only helpers and grants are not included in the public popup build. Tests exercise
these boundaries in isolation and through the generated scripts; a DOM harness cannot establish
userscript-manager, Trusted Types or browser layout compatibility by itself.

`make check-types` runs strict TypeScript (`tsc -p tsconfig.json`) over the JSDoc contract of the
modules listed in `tsconfig.json`: the offline review store, the pure local-mode helpers, the shared
dictionary/popup-protocol/nom-match modules and most of `scripts/lib/`. It checks the existing
JavaScript without transpiling or adding a runtime dependency; `make verify` runs the same check.
The DOM-heavy runtimes are not listed yet; add a module to the `files` array once it passes
without `@ts-nocheck`.
