## 2. Lock and journal primitives

- [x] 2.1 Implement import-safe atomic lock-directory acquisition/release with a unique token and owner metadata. (`scripts/add-chu-nom/lock.js`: `acquireLock`/`releaseLock`. Exclusivity comes from a single `fs.mkdirSync` on the lock subdirectory, which fails with `EEXIST` if another process already holds it; owner metadata (token, pid, best-effort process-start signature, operation, manifest path, timestamp) is written only after that directory is exclusively created. No module-load-time filesystem access.)
- [x] 2.2 Implement atomic phase/file-hash journal updates and conservative local owner-liveness checks without external dependencies. (`scripts/add-chu-nom/journal.js`: `writeJournal`/`readJournal`/`clearJournal`, atomic via the existing `lib/fsutil.atomicWrite`. `lock.js`: `isProcessAlive` (via `process.kill(pid, 0)`), `processStartSignature`/`isOwnerLive` (best-effort `ps -o lstart=` identity check to catch PID reuse after a crash; falls back to conservative "still alive" when the signature cannot be read).)
- [x] 2.3 Implement explicit recovery planning/execution that never steals a merely old or ambiguously owned lock. (`scripts/add-chu-nom/lock.js`: `planRecovery` (read-only; returns `clean`/`live`/`recoverable`/`ambiguous`/`needs_operator_recovery`, never based on age alone) and `recover` (only ever mutates on a `recoverable` plan; every other status throws `workflow_lock_recovery_required` with diagnostic `details`).)
- [x] 2.4 Unit-test lock contention, token mismatch, PID/start identity, journal corruption, ambiguous ownership, and safe no-mutation recovery. (`test/add-chu-nom-lock.test.js`, 12 tests: contention/busy, token-mismatch release refusal, live-owner detection, dead-PID recovery, corrupt-owner ambiguity, partially-written-file refusal, clean-preimage recovery, `isProcessAlive` for a real vs. nonexistent PID, journal corruption/round-trip.)

## 3. Workflow integration

- [x] 3.1 Wrap every review-manifest mutation in the repository-scoped lock and preserve comment/decision behavior. (`scripts/add-chu-nom.js`, `review` command: acquires the lock before re-reading the manifest, applies decisions, writes, then releases -- same lock apply uses, so review and apply are mutually exclusive too. Existing decision-recording behavior (`applyDecisions`) is untouched; `test/add-chu-nom.test.js`'s existing review tests all still pass unmodified.)
- [x] 3.2 Acquire the same lock before apply's final reads and hold it through post-lock hash validation, snapshot, writes, builds, verification, rollback, and commit. (`scripts/add-chu-nom/apply.js`: `applyManifest` now acquires the lock first and only then calls `applyManifestLocked`, which does every read/mutation/build/verify/rollback step; the lock is released in a `finally` (except when a recovery-required rollback failure deliberately keeps it held -- see 3.4).)
- [x] 3.3 Recompute all influencing source hashes after lock acquisition and return the stable stale-plan result before snapshot/write when they differ. (Moving lock acquisition ahead of `validateManifest` means the existing hash revalidation in `manifest.js`'s `collectManifestIssues` -- which was already always re-reading current file hashes against `manifest.sourceHashes` -- now runs *after* this process is the sole owner of the workflow, so a queued session's `stale_source` result is now guaranteed accurate instead of racy. Proven by the concurrency test in 1.1/4.1.)
- [x] 3.4 Guard rollback with lock-token and post-write-hash checks so foreign or manually changed bytes are never overwritten. (`scripts/add-chu-nom/fsutil.js`: `guardedRestoreSnapshot(snapshot, writtenHashes)` only restores a file if its current bytes are still the pre-transaction preimage or exactly what this transaction's own tracked writes produced; anything else throws `workflow_lock_recovery_required` instead of overwriting. `apply.js` tracks `writtenHashes` after every mutating step and, if the guard refuses, deliberately leaves the lock held (skips `releaseLock`) instead of releasing it over an unresolved state.)
- [x] 3.5 Add default fail-fast contention and explicit bounded-wait/recovery CLI options with compact human/JSON results and stable exit codes. (`scripts/add-chu-nom.js`: `--wait-ms` on `review`/`apply` (defaults to 0 = fail fast), new `recover` command. `errors.js`: `EXIT_CODES.WORKFLOW_BUSY` (5) and `EXIT_CODES.RECOVERY_REQUIRED` (6) alongside the existing codes; every new error carries a `hint` like the rest of the error table.)
